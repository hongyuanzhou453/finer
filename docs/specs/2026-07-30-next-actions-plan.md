## P1 — F2 定向验证（我来做，**待你确认设计**）

**这是本阶段的核心建设项**，同时解决两件事：可信度检验的样本缺口 + F2 召回这个
全链唯一真瓶颈（07-30 已确诊：`scan_text` 只匹配注册表别名，从不扫正文里的 ticker）。

### 设计要点（与已否决的「裸模式扫描」的区别是决定性的）

裸扫描已实测**不安全**：法律声明缩写（`C.T.V.M.` → `C.T`）、PDF 乱序残片（`NE.T`）、
单双字母码（`L.L`、`P`）会批量产生假锚点——假锚点比缺锚点危害大，直接污染可审计性。

定向验证改为**闭集**：

```
对每条搁浅 intent（T3 已声明 target_symbol = 如 4091.T）：
  1. 只在该 intent 所属信封的正文里找这一个代码（及其归一化变体）
  2. 上下文门：拒绝法律声明段、乱序文本段（非词序特征可检测）、表格页脚
  3. 命中 → 生成真实 EvidenceSpan（带 char offset）→ 走 canonical F5
  4. 未命中 → 保持搁浅，不伪造
```

每篇只验 1–2 个候选，且 T3 抽取本身是独立证据源——本质是把 A3 的「声明式」原则
用到证据层：**T3 说了什么，就只验证那一件事**。

### 执行纪律（沿用本轮已验证的流程）

1. 设计评审（本文即设计稿，你点头后开工）

## P1.5 — A 桶诊断（我来做，顺手，半小时）

搁浅原因里 41.2% 是「正文根本没提该标的」。抽 30 条对照**原始 PDF**：
- 若名字在 PDF 的图片页上（F1 文本层没覆盖）→ 归 OCR 决策的收益侧，喂 P4
- 若 PDF 里确实没有 → **T3 抽取幻觉**，影响对 T3 数据的信任度，需要记录污染率

这个数字直接决定 L3（OCR）值不值得做。
